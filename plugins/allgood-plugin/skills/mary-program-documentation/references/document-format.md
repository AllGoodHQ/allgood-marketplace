# Program Documentation — Format Specification

This is the complete formatting reference for building program documentation DOCX files.
Follow it precisely when constructing tables, labels, and layout.

---

## Page Setup

| Property | Value | Notes |
|---|---|---|
| Page Margins (Top/Bottom) | 1 inch (1440 DXA) | Standard margins |
| Page Margins (Left/Right) | 0.75 inch (1080 DXA) | Slightly narrower for wider tables |
| Total Table Width | 10320 DXA | Fills page width within margins |
| Default Font | Arial | Used throughout |
| Default Font Size | 11pt (22 half-points) | Body text size |

## Cover Page (Page 1)

The first page is a branded title page. It has **no header and no footer** — the
standard header/footer only appear on content pages (page 2 onward). Use a separate
section in the DOCX with `differentFirstPage` or a section break to suppress
headers/footers on page 1.

### Layout (top to bottom, all centered)

```
[~1 inch top margin]

[Mary logo — centered, ~1.5 inches / 2160 DXA wide]
  assets/mary-logo.png — display circular with pink #dc4393 border if possible

[~0.3 inch gap]

"powered by"  [allGood logo inline]
  "powered by" — Regular, 11pt, Medium Gray (#888888)
  allgood-logo.png — ~0.6 inches / 864 DXA wide, vertically centered with text

[~0.5 inch gap]

────────────────────────────────────────────────────
  Pink horizontal rule: 2pt solid #dc4393, full page width (10320 DXA)

[~0.5 inch gap]

"PROGRAM DOCUMENTATION"
  Eyebrow label — Bold, 13pt, Pink (#dc4393), uppercase, centered
  Letter spacing: expanded (~1pt / 20 DXA)

[~0.2 inch gap]

"NL - 2025.03.12"                         ← Program code/prefix (if present)
  Regular, 20pt (40 half-points), Dark Gray (#666666), centered
  Only include if the program name has a recognizable prefix/code portion

"allGood Customer Newsletter"             ← Program name (descriptive portion)
  Bold, 26pt (52 half-points), Black, centered
  If no prefix, show the full program name here at this size

[~0.4 inch gap]

┌─────────────┬─────────────┬─────────────┐
│  Newsletter  │ Email Program│   Unlocked   │
│   Channel    │     Type     │    Status    │
└─────────────┴─────────────┴─────────────┘
  Pill table — 3 cells, centered on page
  Total width: ~7800 DXA (narrower than page, for visual centering)
  Each cell: ~2600 DXA
  Line 1 (value): Bold, 13pt, Pink (#dc4393), centered
  Line 2 (label): Regular, 10pt, Medium Gray (#888888), centered
  Cell background: Light Gray (#efefef)
  Cell margins: Top/Bottom: 120 DXA, Left/Right: 100 DXA
  Borders: Single, 1pt, #CCCCCC on all sides

[~0.5 inch gap]

────────────────────────────────────────────────────
  Pink horizontal rule: 2pt solid #dc4393, full page width

[~0.3 inch gap]

"Program ID: 1634  |  Workspace: Default  |  Generated: 04/16/2026"
  Centered, Regular, 10pt, Medium Gray (#888888)
  Pipe separators with extra spacing

"Folder: Marketo Template Auto Create  |  Last Modified: 03/05/2026"
  Centered, Regular, 10pt, Medium Gray (#888888)
  Second line of metadata

[push to bottom of page — use spacing or vertical alignment]

"For internal use only  •  Generated by Mary, powered by allGood"
  Centered, Italic, 9pt, Medium Gray (#888888)
  Use bullet (•) as separator
  Position near the bottom of the page (~0.75 inch from bottom margin)
```

### Technical Notes for Cover Page

**Suppressing header/footer on page 1:**

```javascript
// In docx-js, use sections with different header/footer settings
sections: [
  {
    // Cover page section — no header/footer
    properties: {
      titlePage: true,  // enables different first page
      // ... margins
    },
    headers: { first: new Header({ children: [] }) },  // empty
    footers: { first: new Footer({ children: [] }) },  // empty
    children: [ /* cover page content */ ]
  }
]
```

Or use two sections: cover page section (no header/footer) with a section break,
then content section (with header/footer).

**Pink horizontal rule:**

```javascript
new Paragraph({
  border: {
    bottom: { style: BorderStyle.SINGLE, size: 2, color: "dc4393", space: 1 }
  },
  spacing: { before: 400, after: 400 }
})
```

**Pill table centering:**

```javascript
new Table({
  alignment: AlignmentType.CENTER,
  width: { size: 7800, type: WidthType.DXA },
  // ... rows and cells
})
```

**Vertical spacing to push footer note to bottom:**
Use a paragraph with large `before` spacing, or calculate remaining space.
Alternatively, use a text frame or footer-like positioning.

### After Cover Page

Insert a **page break** (or section break) immediately after the cover page content.
All subsequent pages should have the standard header ("Program Documentation") and
footer (Mary logo + "powered by" + allGood logo).

## Section Headers

- **Style:** Heading 2
- **Font:** Arial, 16pt (32 half-points)
- **Weight:** Bold
- **Color:** Pink (`#dc4393`)
- **Spacing:** 400 DXA before, 200 DXA after

**Section Types:**

1. Overview
2. Configuration
3. Asset Inventory
4. Program Logic Flow
5. Health / QA Flags
6. Performance Snapshot

---

## Sub-Headings (Asset Groups)

Used within Section 3 (Asset Inventory) to separate asset types.

- **Font:** Arial, 13pt (26 half-points)
- **Weight:** Bold
- **Color:** Dark Gray (`#666666`)
- **Spacing:** 300 DXA before, 150 DXA after

**Sub-heading types:** Smart Campaigns, Emails, Landing Pages, Forms,
Smart Lists & Static Lists, My Tokens

---

## Table Types

### Type A: Key-Value Table (2-Column)

Used for Overview, Configuration, and Performance Snapshot sections.
Simple label → value pairs for program metadata.

| Property | Value |
|---|---|
| Columns | 2 |
| Column 1 Width | 3200 DXA (Label) |
| Column 2 Width | 7120 DXA (Value) |
| Total Width | 10320 DXA |
| Row Background | Alternating: White → Gray (`#efefef`) → White... |
| Cell Margins | Top/Bottom: 100 DXA, Left/Right: 140 DXA |
| Borders | Single, 1pt, Gray (`#CCCCCC`) on all sides |

**Column 1 (Label):**
- Bold, 11pt, Dark Gray (`#666666`)

**Column 2 (Value):**
- Regular, 11pt, Black
- Missing/null values: Italic, 11pt, Medium Gray (`#888888`), e.g. *"Not set"*

---

### Type B: Asset Inventory Table (4-Column)

Used for listing smart campaigns, emails, landing pages, forms, and lists.
Includes a pink row number column for visual scanning.

| Property | Value |
|---|---|
| Columns | 4 |
| Column 1 Width | 720 DXA (Row Number) |
| Column 2 Width | 3600 DXA (Asset Name) |
| Column 3 Width | 2400 DXA (Details) |
| Column 4 Width | 3600 DXA (Status / Notes) |
| Total Width | 10320 DXA |
| Cell Margins | Top/Bottom: 100 DXA, Left/Right: 140 DXA |
| Borders | Single, 1pt, Gray (`#CCCCCC`) on all sides |

**Header Row:**
- Background: Dark Gray (`#666666`)
- Text: White, Bold, 11pt
- Columns: "#" | "Name" | "Details" | "Status"

**Column 1 (Row Number):**
- Background: Pink (`#dc4393`) — always, regardless of row alternation
- Text: White (`#FFFFFF`), Bold, 12pt (24 half-points), Centered

**Columns 2-4:**
- Row Background: Alternating White / Gray (`#efefef`)
- Text: Regular, 11pt, Black

---

### Type C: Token Table (3-Column)

Used for the My Tokens sub-section within Asset Inventory.

| Property | Value |
|---|---|
| Columns | 3 |
| Column 1 Width | 3200 DXA (Token Name) |
| Column 2 Width | 2400 DXA (Type) |
| Column 3 Width | 4720 DXA (Value) |
| Total Width | 10320 DXA |
| Cell Margins | Top/Bottom: 100 DXA, Left/Right: 140 DXA |
| Borders | Single, 1pt, Gray (`#CCCCCC`) on all sides |

**Header Row:**
- Background: Dark Gray (`#666666`)
- Text: White, Bold, 11pt
- Columns: "Token Name" | "Type" | "Current Value"

**Column 1 (Token Name):**
- Format as `{{my.TokenName}}` — Bold, 10pt, Black
- Token name should be the exact Marketo token syntax

**Column 2 (Type):**
- Regular, 10pt, Dark Gray (`#666666`)
- Values: text, rich text, date, number, score, sfdc campaign

**Column 3 (Value):**
- Regular, 10pt, Black
- Truncate at 200 characters with "..."
- Rich text tokens: strip HTML, show plain text + "(rich text)" in italic gray
- Empty/placeholder values: Italic, Medium Gray (`#888888`)

**Row Background:** Alternating White / Gray (`#efefef`)

---

### Type D: Health Flag Table (3-Column)

Used for Section 5 — Health / QA Flags.

| Property | Value |
|---|---|
| Columns | 3 |
| Column 1 Width | 1200 DXA (Severity) |
| Column 2 Width | 4200 DXA (Flag Description) |
| Column 3 Width | 4920 DXA (Recommendation) |
| Total Width | 10320 DXA |
| Cell Margins | Top/Bottom: 120 DXA, Left/Right: 140 DXA |
| Borders | Single, 1pt, Gray (`#CCCCCC`) on all sides |

**Header Row:**
- Background: Dark Gray (`#666666`)
- Text: White, Bold, 11pt
- Columns: "Severity" | "Issue" | "Recommendation"

**Column 1 (Severity Badge):**

| Severity | Background | Text |
|---|---|---|
| Critical | `#DC3545` (red) | White, Bold, 10pt, Centered |
| Warning | `#F39C12` (orange) | White, Bold, 10pt, Centered |
| Info | `#4A90D9` (blue) | White, Bold, 10pt, Centered |

**Column 2 (Flag):**
- Regular, 11pt, Black
- Concise description of the issue

**Column 3 (Recommendation):**
- Regular, 10pt, Dark Gray (`#666666`)
- Actionable guidance on what to do

**No-issues row:** If zero flags detected, single full-width row:
- Background: `#28A745` (green)
- Text: White, Bold, 11pt, Centered
- Content: "No issues detected — program configuration looks healthy"

### Type E: Smart Campaign Detail Block

Used in Section 4 — Program Logic Flow. One block per smart campaign.

This is a composite structure, not a single table. Build it as a sequence of elements:

**1. Campaign Header Row (full-width table, 1 row)**

| Property | Value |
|---|---|
| Width | 10320 DXA |
| Background | White |
| Left Border | 4pt solid Pink (`#dc4393`) — left side only |
| Cell Margins | Top/Bottom: 120 DXA, Left: 200 DXA, Right: 140 DXA |

Content:
- Line 1: Campaign name — Bold, 12pt, Black
- Line 2: Type (Trigger / Batch / Executable) + " | " + Status (Active / Inactive)
  — Regular, 10pt, Dark Gray (`#666666`)

**2. Smart List Sub-Section**

Below the header, add a label paragraph:
- "Smart List (Triggers & Filters)" — Bold, 11pt, Dark Gray (`#666666`)
- Spacing: 200 DXA before, 100 DXA after

Then a 3-column table for rules:

| Property | Value |
|---|---|
| Column 1 Width | 1200 DXA (Rule Type: "Trigger" or "Filter") |
| Column 2 Width | 4200 DXA (Rule Name + Attribute) |
| Column 3 Width | 4920 DXA (Operator + Values) |
| Total Width | 10320 DXA |
| Borders | Single, 1pt, `#CCCCCC` |

- Trigger rows: Column 1 background Pink (`#dc4393`), white bold text
- Filter rows: Column 1 background Light Gray (`#efefef`), dark gray text
- Filter logic row (if advanced): full-width merged row at bottom showing
  "Logic: 1 AND (2 OR 3)" in italic

**3. Flow Steps Sub-Section**

Label paragraph:
- "Flow Steps" — Bold, 11pt, Dark Gray (`#666666`)
- Spacing: 200 DXA before, 100 DXA after

Then a 3-column table:

| Property | Value |
|---|---|
| Column 1 Width | 720 DXA (Step Number) |
| Column 2 Width | 3200 DXA (Action Name) |
| Column 3 Width | 6400 DXA (Details / Parameters / Choices) |
| Total Width | 10320 DXA |
| Borders | Single, 1pt, `#CCCCCC` |

- Column 1: Pink background, white bold text, centered (step number)
- Column 2: Bold, 11pt, Black (action name like "Send Email", "Wait", "Change Status")
- Column 3: Regular, 10pt, Black (parameters, choice step conditions, wait durations)
  - Choice steps: indent with "If [condition] → [action]" on separate lines
  - Default choice: "Default: [action]"

**4. Qualification & Schedule Row**

Single full-width row below the flow steps:

| Property | Value |
|---|---|
| Background | Light Gray (`#efefef`) |
| Text | Regular, 10pt, Dark Gray |

Content: "Qualification: [Once / Every time / Every N days] | Schedule: [details or N/A]
| Requestable: [Yes/No]"

**5. Spacing**

After each complete campaign block, add 1 empty paragraph before the next block.

|---|---|

## Row Alternation Pattern

Rows alternate between white and gray backgrounds for readability:

| Row | Background |
|---|---|
| 1 (after header) | White (`#FFFFFF`) |
| 2 | Gray (`#efefef`) |
| 3 | White |
| ... | continues... |

**Exception:** Pink row number columns (Types B and E flow steps) always stay pink
regardless of alternation.

## Technical Notes (for docx-js implementation)

### Cell Margins

```javascript
margins: { top: 100, bottom: 100, left: 140, right: 140 }
```

### Border Definition

```javascript
const tableBorder = { style: BorderStyle.SINGLE, size: 1, color: "CCCCCC" };
const cellBorders = {
  top: tableBorder,
  bottom: tableBorder,
  left: tableBorder,
  right: tableBorder
};
```

### Shading (Background Color)

```javascript
shading: { fill: "efefef", type: ShadingType.CLEAR }
```

**Important:** Always use `ShadingType.CLEAR`, never `ShadingType.SOLID`.

### Left Border Only (Campaign Header)

```javascript
borders: {
  left: { style: BorderStyle.SINGLE, size: 4, color: "dc4393" },
  top: { style: BorderStyle.NONE },
  bottom: { style: BorderStyle.NONE },
  right: { style: BorderStyle.NONE }
}
```

|---|---|---|

## Quick Reference Checklist

When building a program documentation DOCX:

**Cover page:**
- [ ] Mary logo centered near top
- [ ] "powered by" + allGood logo centered below
- [ ] Pink horizontal rule (2pt, `#dc4393`)
- [ ] "PROGRAM DOCUMENTATION" eyebrow — pink, bold, uppercase, centered
- [ ] Program name in large bold type, centered
- [ ] 3-cell pill table (Channel | Type | Status) — centered, pink text, gray bg
- [ ] Second pink horizontal rule
- [ ] Metadata lines (Program ID, Workspace, Generated, Folder, Last Modified)
- [ ] Footer note: "For internal use only" — italic gray, near bottom
- [ ] NO header/footer on cover page
- [ ] Page break after cover page

**Content pages:**
- [ ] Set page margins (1" top/bottom, 0.75" left/right)
- [ ] Use Arial font throughout
- [ ] Apply pink (`#dc4393`) to section headers
- [ ] Header: "Program Documentation" left-aligned in pink (content pages only)
- [ ] Footer: right-aligned — Mary logo (288 DXA) + "powered by" gray 9pt + allGood logo (432 DXA)
- [ ] All 6 sections present with correct headers
- [ ] Key-Value tables: 3200 DXA label / 7120 DXA value
- [ ] Asset tables: pink row numbers, dark gray header row
- [ ] Token table: 3 columns, monospace-style names
- [ ] Health flags: correct severity colors (red/orange/blue)
- [ ] Campaign detail blocks: pink left border, smart list + flow steps + qualification
- [ ] Alternating row backgrounds (white / `#efefef`)
- [ ] All borders: single, 1pt, `#CCCCCC`
- [ ] Cell margins applied per table type
- [ ] Null values shown as italic gray *"Not set"*
